Brimp provides self-contained wheels for **Python 3.11+** and platform packages
for **Node.js 22.19+**:

| Platform | Python | Node.js |
| --- | --- | --- |
| macOS arm64 (11+) | `pip install brimp` | `npm install @brimp/brimp` |
| Linux x86_64 (glibc 2.34+) | `pip install brimp` | `npm install @brimp/brimp` |
| Linux arm64 (glibc 2.34+) | `pip install brimp` | `npm install @brimp/brimp` |
| Windows x64 | `pip install brimp` | `npm install @brimp/brimp` |

The packages bundle JavaScriptCore, ICU, curl-impersonate and the Visual C++
runtime DLLs required by the Windows SDK. Intel macOS and Windows arm64 are not
published.

## Verify the runtime

```python
from brimp import Session

with Session() as session:
    page = session.new_page()
    print(page.evaluate("typeof document.querySelector"))
```

Expect `function`. The same check for Node.js:

```js
import { createSession } from '@brimp/brimp';

const session = await createSession();
try {
  const page = await session.newPage();
  console.log(await page.evaluate('typeof document.querySelector'));
} finally {
  await session.close();
}
```

Browser subsystem plugins are enabled by default. An explicit `plugins` list
replaces them; use `plugins=[]` (Python) or `plugins: []` (Node.js) for core
execution only.

## Build from source

Use this path for the CLI or when changing the runtime. You need Rust/Cargo and
the native SDK build tools. Lexbor is vendored; WebCrypto uses the BoringSSL
instance in curl-impersonate.

### 1. Prepare the native SDKs

`scripts/prepare_native.py` downloads the pinned JavaScriptCore and
curl-impersonate releases and prints the environment required to link them:

```sh
git clone https://github.com/lexiforest/brimp.git
cd brimp
python3 scripts/prepare_native.py \
  --target aarch64-apple-darwin \
  --output .native/release \
  --curl-release
```

Use `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` or
`x86_64-pc-windows-msvc` as appropriate. The script writes
`BRIMP_JSC_LIB_DIR`, `BRIMP_CURL_LIB_DIR`, `BRIMP_LICENSE_DIR` and the loader
paths to `$GITHUB_ENV` when running in GitHub Actions, and prints them otherwise.

To link a source-built curl SDK instead, pass `--curl-sdk /path/to/prefix` and
omit `--curl-release`.

### 2. Build an interface

CLI:

```sh
cargo install --path crates/cli --locked
brimp doctor
```

Expect JSON with `javascriptCore`, `lexbor`, `libcurlImpersonate` and `crypto`
set to `ok`. The executable still needs the SDK libraries at runtime.

Python, into a virtual environment:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install maturin
maturin develop --manifest-path bindings/python/Cargo.toml
```

Node.js, from the checkout:

```sh
cargo build -p brimp-python -p brimp-node
python3 bindings/prepare_local.py
npm install ./bindings/node
```

On Windows, activate the virtual environment with
`.venv\Scripts\Activate.ps1` in PowerShell.
